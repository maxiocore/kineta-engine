## CRITICAL — NOT fixed (needs your approval: changes payment behaviour)
- **W1 Wallet self-edit**: policy "Users can update their own balance" (+ "insert their own balance") lets any customer set their own `balance` from the browser. Five order/payment screens (design order, professional/embedded/custom order forms, invoice payment) debit the wallet *from the browser* and compute `total_price` client-side. Fix = move these to one server-side atomic RPC (like `order_cloud_server`) and then drop the self-update policy. Changing it alone would break those payments.
- **W2 Client-set order prices**: same screens insert `orders` with browser-computed prices. Fixed together with W1.

## HIGH — NOT fixed (needs approval)
- **H1 profiles**: every signed-in user can read every profile (email, phone). Sign-in by SMS/WhatsApp and several pages look up profiles; restricting needs those lookups moved server-side first.
- **H2 referrals**: anyone can insert a referral row → possible commission fraud. Sign-up inserts it before a session exists; needs a server-side step.
- **H3 cloud_orders**: a customer can read cost/margin/exchange-rate columns of *their own* order (no cross-customer leak). Fix = customer-safe view; admin pages unaffected.
- **H4 Leaked-password protection** off (one-click setting; affects new passwords only).

## MEDIUM / LOW / INTENDED
- contact_messages, job_applications, resumes upload: public by design (forms/CV upload for visitors); bucket private, admin-only read. Rate limiting recommended (MEDIUM).
- admin_notifications insert by any signed-in user: spam risk only (LOW).
- cloud_billing_settings read by signed-in users: VAT rate needed in checkout (INTENDED).
- disposable_email_domains public read: INTENDED.
